# Протокол «Отправить на Lumen Play»

Как расширение браузера (`extension/`) передаёт видео со страницы в Lumen Play на проекторе.
Обе стороны реализуют ровно это; если что-то меняется, сначала правится этот файл.

## Транспорт

- Lumen Play держит маленький HTTP-сервер на **TCP 8765**, пока приложение установлено:
  запускается из уже существующего приёмника `BOOT_COMPLETED` и при старте приложения.
  Один небольшой пул потоков, мало памяти, ничего другого не останавливает.
- Сервер объявляет себя в сети через NSD: тип службы `_lumenplay._tcp`, порт 8765.
  Браузеры NSD/mDNS не видят, поэтому расширение ищет проектор по адресу или перебором
  своей подсети /24 запросом `GET /lumen/info`.
- Тела запросов и ответов: JSON в UTF-8, `Content-Type: application/json`.
- Тело запроса не больше **64 КБ**, иначе `413`.
- CORS: запросы с `Origin`, начинающимся с `chrome-extension://` или `moz-extension://`,
  получают `Access-Control-Allow-Origin: <тот же Origin>`,
  `Access-Control-Allow-Methods: GET, POST, OPTIONS`,
  `Access-Control-Allow-Headers: Authorization, Content-Type`,
  `Access-Control-Max-Age: 600`, `Access-Control-Allow-Private-Network: true`. Предзапрос
  `OPTIONS` отвечает `204`. Запрос без `Origin` (curl) обслуживается без CORS-заголовков.
  Запрос с любым другим `Origin` (обычная веб-страница) получает `403 forbidden_origin`:
  иначе любой сайт мог бы выводить коды на экран проектора.
- Если порт 8765 занят, сервер берёт любой свободный; NSD объявляет фактический порт.

## Ошибки

Любая ошибка: код HTTP и тело `{"error":"<код>","message":"<по-русски>"}`.

| HTTP | `error` | Когда |
|---|---|---|
| 400 | `bad_request` | Неверный JSON, нет обязательного поля, ссылка не http/https |
| 401 | `unauthorized` | Нет заголовка `Authorization` или токен неизвестен (в том числе удалён в настройках) |
| 403 | `bad_code` | Неверный код привязки; в теле ещё `"attemptsLeft": <сколько осталось>` |
| 403 | `forbidden_origin` | `Origin` не из расширения (см. CORS) |
| 404 | `not_found` | Неизвестный путь |
| 405 | `method_not_allowed` | Путь есть, метод не тот |
| 409 | `no_pairing` | `confirm` без активного кода (не запрашивали или прошло 60 с) |
| 409 | `background_blocked` | `play`: Android не даёт открыть плеер из фона (Lumen Play не на экране и нет разрешения «поверх других приложений»); на проекторе тоже появляется подсказка |
| 413 | `too_large` | Тело больше 64 КБ |
| 429 | `locked` | 5 неверных кодов подряд: привязка закрыта на 5 минут; в теле ещё `"retryAfter": <секунды>` |

## Методы

### `GET /lumen/info` (без токена)

```json
{"app":"Lumen Play","version":"1.3","name":"XGIMI Z9X","paired":false}
```

`name`: имя устройства. `paired`: есть ли хотя бы один токен на проекторе (это не значит, что
привязан именно этот браузер). Секретов в ответе нет.

### `POST /lumen/pair` (без токена)

```json
{"client":"Chrome на macOS"}
```

Проектор показывает поверх любого приложения четырёхзначный код и имя клиента на 60 секунд.
Новый запрос заменяет старый код, но не раньше чем через 5 секунд: повтор в первые 5 секунд
возвращает тот же код (защита от перебора кодов листанием). Ответ: `{"ok":true,"expiresIn":60}`.
Если привязка закрыта после неверных кодов: `429 locked`.

### `POST /lumen/pair/confirm` (без токена)

```json
{"code":"1234"}
```

Ответ: `{"token":"<64 hex-символа, 32 случайных байта>"}`. Код одноразовый, после успеха
плашка с кодом убирается. Токены хранятся в настройках приложения, не больше 8: девятый
вытесняет самый старый. В настройках Lumen Play их можно посмотреть (имя клиента, дата) и
удалить. После 5 неверных кодов подряд привязка закрыта на 5 минут (`429`).

### `POST /lumen/play` (с токеном)

Заголовок `Authorization: Bearer <token>`.

```json
{
  "url": "https://cdn.example.com/video/master.m3u8",
  "type": "hls",
  "headers": {"Referer": "https://example.com/watch/1", "Origin": "https://example.com", "User-Agent": "Mozilla/5.0 ..."},
  "title": "Название видео",
  "pageUrl": "https://example.com/watch/1",
  "position": 754.2,
  "subtitles": [{"url": "https://example.com/subs/ru.vtt", "lang": "ru", "label": "Русские"}]
}
```

- `url` обязателен, только `http` и `https`.
- `type`: `hls`, `dash`, `progressive` или `auto` (по умолчанию `auto`: тип определяет
  `StreamRequest.streamMime` по ссылке).
- `headers`: только то, что нужно потоку; расширение шлёт `Referer`, `Origin`, `User-Agent`.
  Куки по умолчанию не передаются. Плеер фильтрует заголовки так же, как для интента VIEW.
- `position`: секунды, с какого места начать; `0` или нет поля: с начала.
- `title`, `pageUrl`, `subtitles` необязательны.

Lumen Play открывает `PlayerActivity` тем же путём, что и интент VIEW (`StreamRequest`), и
перематывает на `position`. Ответ `{"ok":true}`.

### `POST /lumen/control` (с токеном)

```json
{"action":"seek","position":120}
```

`action`: `pause`, `play`, `seek` (нужен `position` в секундах) или `stop` (закрыть плеер).
Ответ `{"ok":true}`; если плеер не открыт: `{"ok":false}` (HTTP 200).

### `GET /lumen/state` (с токеном)

```json
{"playing":true,"position":812.4,"duration":5421.0,"title":"Название видео"}
```

Плеер закрыт: `{"playing":false,"position":0,"duration":0,"title":null}`. Для прямого эфира
`duration` равен `0`.

## Как устроено на проекторе

- Сервер: `app/src/main/java/com/xgimiru/player/send/SendServer.kt`, живёт в службе
  `dlna/DlnaService` (одна служба переднего плана для DLNA и для этого приёмника; DLNA можно
  выключить в настройках, приёмник работает всегда). HTTP-слой общий с DLNA (`dlna/HttpServer`):
  до 4 потоков, без запросов они засыпают.
- NSD: имя службы «Lumen Play на <имя устройства>», атрибуты `path=/lumen`, `version`.
- Разбор запросов и проверка ссылок: `send/SendProtocol.kt`; коды и токены: `send/Pairing.kt`.
  В настройках приложения хранится только SHA-256 токена, сам токен знает только браузер.
- Код на экране: табличка поверх всех окон, если у Lumen Play есть разрешение «поверх других
  приложений»; иначе уведомление и повторяющийся Toast, пока код действует. Пока разрешения
  нет, в настройках Lumen Play виден пункт «Разрешить открываться поверх других приложений»,
  он открывает системный экран этого разрешения.
- Служба поднимается при включении устройства, после обновления Lumen Play
  (`MY_PACKAGE_REPLACED`) и при открытии приложения.
- `play`: интент VIEW в `PlayerActivity` с `title`, `position` (мс; `from_start` при 0),
  заголовками в extra `headers` и субтитрами в extra `subs`; тип `hls`/`dash` уходит MIME-типом
  интента. В `state` есть ещё поле `state`: `loading`, `playing`, `paused` или `stopped`;
  `title` заполняется, только если играет то, что прислали через `play`.
- Список устройств в настройках Lumen Play: «Устройства, которым разрешено отправлять видео»,
  нажатие на строку убирает устройство (токен перестаёт работать сразу).

## Чего протокол не делает

Только видео, которое страница сама играет в открытом виде (mp4/webm, HLS, DASH). Видео под
DRM (Widevine, PlayReady, FairPlay) не передаётся: расширение это определяет и прямо говорит.
Нет блокировки или пропуска рекламы, нет скачивания, нет обхода защиты.
